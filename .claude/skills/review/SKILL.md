먼저 `python3 scripts/run_tests.py <인자>`를 실행해 통과 상태인지 확인한다.
통과하지 않았으면 리뷰를 거부하고 먼저 풀라고 말한다.

통과했다면 `solution.py`를 읽고 다음 순서로 리뷰한다.

### 1. 관용구 압축 가능성 (최우선)

CLAUDE.md의 학습 목표 목록을 기준으로, 이 코드에서 다음이 가능한지 본다.

- `for` 문 → 슬라이싱 / 컴프리헨션
- 인덱스 수동 관리 → `enumerate`
- `if-elif` 사슬 → 딕셔너리
- 수동 카운팅 → `Counter`
- 수동 최솟값 탐색 → `min(key=)`

### 2. 답을 바로 주지 않는다

압축 가능한 지점을 발견하면 **그 지점과 사용할 관용구 이름만** 알려준다.

예: "6~10행의 반복문은 슬라이싱 하나로 줄일 수 있습니다. `[start:stop:step]`의
step 인자를 생각해보세요."

고친 코드를 먼저 보여주지 않는다. 사용자가 시도한 뒤 다시 요청하면 그때 비교한다.

### 3. 시간복잡도

현재 복잡도를 한 줄로 알려주고, 개선 여지가 있으면 그 사실만 언급한다.

### 4. note.md 갱신 제안

리뷰에서 나온 관용구를 `note.md`의 "새로 익힌 관용구" 섹션에 추가할 항목으로 제안한다.
직접 쓰지 말고 제안만 한다. 기록은 사용자가 직접 하는 것이 학습에 남는다.
